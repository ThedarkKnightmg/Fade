## 2. App content (Policy → App content)

### Privacy policy
`https://thedarkknightmg.github.io/Fade/privacy.html`

### App access → "All or some functionality is restricted"
Reviewers can't receive an SMS. Before submitting, add a **test phone number** in Supabase
(Dashboard → Authentication → Sign In / Providers → Phone → *Test phone numbers and OTPs*):
`998900000000=123456`. It always accepts that code, only for that number, and no SMS is sent.

Instructions to paste for the reviewer:
```
Fade requires a sign-in.
1. Open the app, choose a language, accept the terms.
2. Tap "No Telegram? Use my phone number".
3. Enter: +998 90 000 00 00
4. Enter the code: 123456
You are signed in as a client. The barber side: Profile → "Become a barber" → Start.
```

### Ads
**No**, the app does not contain ads.

### Content rating (IARC questionnaire)
- Category: **All other app types** (utility / productivity / social-communication)
- Violence, sexuality, language, drugs, gambling: **No** to all
- Users can interact or exchange content (client ⇄ barber chat): **Yes**
- Shares the user's current physical location with other users: **No**
- Allows users to purchase digital goods (VIP, Boost): **Yes**
- Expected result: roughly 12+ / Teen because of the chat.

### Target audience
- Age groups: **18 and over** only (the privacy policy says Fade isn't for children).
- Appeals to children: **No**.

### Data safety
Encryption in transit: **Yes**. Users can request deletion: **Yes**, URL
`https://thedarkknightmg.github.io/Fade/delete-account.html`

| Data type | Collected | Shared | Optional? | Purposes |
|---|---|---|---|---|
| Personal info → **Name** | Yes | Yes (the barber you book) | Required | App functionality, Account management |
| Personal info → **Email address** | Yes | No | Optional (Google sign-in only) | Account management |
| Personal info → **Phone number** | Yes | Yes (the barber you book) | Required | App functionality, Account management, Fraud prevention |
| Location → **Precise location** | Yes | No | Optional | App functionality (nearby shops, arrival check-in) |
| Location → **Approximate location** | Yes | No | Optional | App functionality |
| Photos and videos → **Photos** | Yes | **Yes** (AI preview service, with consent) | Optional | App functionality |
| Messages → **Other in-app messages** | Yes | No | Optional | App functionality |
| App activity → **Other user-generated content** (reviews, bookings) | Yes | Yes (reviews are public) | Optional | App functionality |
| Financial info → **Purchase history** | Yes | No | Optional | App functionality |
| App info and performance → **Diagnostics** | Yes | No | Required | Analytics (app stability) |

Not collected: contacts, calendar, SMS/call logs, files, audio, health, browsing history, device IDs, card numbers.

Notes:
- Supabase (hosting) is a *service provider*, which Google does not count as "sharing".
- Name and phone are marked as shared with the barber, because the privacy policy treats barbers as independent businesses. Under-declaring is a common rejection cause; over-declaring is not.
- The AI selfie is marked as shared to be safe, because it goes to a third-party service.

### Other declarations
- Government app: No · Financial features: **None** (Fade sells its own service; it does not offer loans, banking or crypto) · Health: No · News: No · COVID: No
- Location: **precise + approximate, foreground only** (map, nearby shops, arrival check-in). No background location, so no extra declaration is needed.
- Camera: used for the QR check-in and for photos the user chooses.

## 3. Closed testing track
1. Testing → Closed testing → Create track (or use "Alpha").
2. Countries: **Uzbekistan** (add Kazakhstan, Kyrgyzstan, Tajikistan, Russia if you want).
3. Testers: the email list you created (at least 15 people).
4. Upload `Fade-1.0.4.aab`, paste the release notes, then Review → Start rollout.
5. Send testers the opt-in link. The 14 days start once 12 or more have opted in.
6. On day 15: Dashboard → **Apply for production**.
